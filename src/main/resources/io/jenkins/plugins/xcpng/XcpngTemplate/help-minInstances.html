Number of pre-booted idle agents of this template to keep hot (a warm pool), so a queued build connects to a ready executor instead of waiting for a cold clone. Defaults to 0, which turns the warm pool off.

Without a spare, a waiting build still gets a clone requested straight away, so a spare saves the time a clone takes to boot and connect. A build arriving while a spare is still booting waits for that spare rather than getting a second clone.

Warm spares count against the cloud's Max instances, so the pool is capped by that limit and a target larger than it can never be filled. Warm agents are still single-use: each runs one build and is then destroyed, and the maintainer clones a replacement to keep the pool at size.

The pool is reconciled about once a minute by a background task, so a spare appears up to a minute after you save the configuration, and a consumed spare's replacement takes up to a minute to appear. A spare that boots but never connects is still reclaimed by the idle timeout.

A controller restart costs every spare its warm marker, which is not persisted on purpose. Every agent the controller reloads is reclaimed at its first retention check, normally within seconds of reconnecting and at most about a minute after startup, and the maintainer clones replacements. A build that reached the old agent first keeps it until that build completes. Until the old agent is gone it counts against Max instances, so a cloud at its cap clones the replacement only once the old one has been destroyed.
