Base URL of the Xen Orchestra appliance in front of the pool, for example https://xo.example.com. The plugin speaks the Xen Orchestra REST API (/rest/v0) to this address, never XAPI to a pool master, so this is the appliance and not the pool. Use an https URL. This form refuses a plain http URL, because every request carries the authentication token. A URL set through configuration as code or a hand-edited config.xml bypasses the form: an http one is only warned about in the system log, and the token is then sent in cleartext. Do not embed a username or password in the URL.

The appliance has to route PATCH /rest/v0/vms/{id}, which the plugin needs to seed each clone. It is absent on xo-server 5.192.1, what a freshly deployed appliance ran when this was measured, and present on 5.208.3. Test connection checks for it and says so if it is missing.
