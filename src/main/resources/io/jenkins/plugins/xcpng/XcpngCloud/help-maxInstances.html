Upper bound on the number of agents this cloud will run at once. The plugin never clones past this limit, so it caps how much of the pool a busy queue can consume. Warm-pool spares (a template's Warm pool size) count towards this total. Raise it to scale throughput; each agent runs a single build, so more concurrent builds means more instances, not more executors per instance.

A waiting build gets a clone as soon as no free or booting agent can take it, so a burst of builds can start as many clones as there is room for under this limit. Agents already registered, warm spares included, take up part of that room. Once the cloud is at this limit, further builds wait for a slot to free up.
