Which API this cloud speaks.
XAPI (direct to the pool)
JSON-RPC straight to a pool master. Needs no Xen Orchestra appliance, and authenticates with a username and password credential. This is the default and what every existing configuration keeps.
Xen Orchestra REST API
The /rest/v0 API on an XO appliance in front of the pool. Requires XO 6.5.0 or newer — the release that added PATCH /vms/{id}, which the plugin needs to seed a clone. Against an older appliance the seed fails as a 404. Authenticates with a secret-text credential holding an XO authentication token, not a username and password.

Pool URL means the appliance when this is set to Xen Orchestra, not the pool master. The credential kind changes with the backend, so switching this normally means selecting a different credential too; Test connection says so if the pair does not match.

The XO backend is new and has not yet been through the lab scenarios the XAPI one was released on. Prefer XAPI unless you are helping to exercise it.
